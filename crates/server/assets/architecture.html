Architecture

What moves between machines, what stays local, and how to provision a container safely.

Local workspaces, shared history

Each agent edits files in a normal local working copy. td embeds Jujutsu and publishes saved changes to the native server in the background. Published operation heads are preserved so concurrent work can converge through jj.

AgentStays localBecomes shared
agent-aworking-copy filespublished jj history
agent-bworking-copy filespublished jj history

Use td log to inspect that history. Tandem does not move another workspace’s files. If your checked-out commit changes elsewhere, including through a descendant rebase, jj marks it stale. Run td workspace update-stale yourself, or set td config set --workspace snapshot.auto-update-stale true to let the next jj command update it. The background daemon never applies the update.

Names and access

Give every agent a distinct workspace name. The installer saves the host owner credential to ~/.config/td/credentials with mode 0600, and td clone uses it to create or attach the named repository. Keep that file private; the server checks repository and workspace scope on every request.

For a container, mount the installer-managed credential file read-only. Use a separately scoped workspace name, volume, and container for every agent.

Docker provisioning

Build a binary-only image

cat <<'DOCKERFILE' | docker build --platform linux/amd64 -t tandem-agent -
FROM debian:bookworm-slim
RUN apt-get update \
 && apt-get install -y --no-install-recommends ca-certificates curl \
 && curl -fsSL @@TANDEM_PUBLIC_URL@@/dl/td-x86_64-unknown-linux-gnu -o /usr/local/bin/td \
 && chmod 755 /usr/local/bin/td \
 && rm -rf /var/lib/apt/lists/*
WORKDIR /work
ENTRYPOINT ["td"]
DOCKERFILE

The Dockerfile arrives on standard input, so no local credential file enters the build context.

Create one workspace, then keep its daemon in the foreground

$ docker volume create tandem-agent-a
$ docker run --rm \
  -v tandem-agent-a:/work \
  -v "$HOME/.config/td/credentials:/root/.config/td/credentials:ro" \
  tandem-agent clone @@TANDEM_PUBLIC_URL@@/you/my-project /work --workspace agent-a
$ docker run -d --rm --name agent-a \
  -v tandem-agent-a:/work \
  -v "$HOME/.config/td/credentials:/root/.config/td/credentials:ro" \
  tandem-agent daemon /work
$ docker exec agent-a sh -lc \
  "printf 'hello from Docker\\n' > /work/hello.txt"

Mount the owner credential only at runtime, and use a separate volume, container name, and --workspace value for every agent. Docker detaches the container, while the foreground daemon stays at PID 1 inside it and publishes file changes made in the mounted workspace.

Implementation detail

The source repository contains the technical architecture describing the client/server boundary, durable write-ahead log, repository materialization, and recovery model.

One workspace has one active writer. Distinct names avoid agents contending for the same writer role.

The bucket write-ahead log and index are the durable authority; local server state can be rebuilt.
